# Как пополнять Omu Design System

Этот репозиторий хранит не просто файлы, а решения бренда вместе с их происхождением и статусом зрелости.

## Перед началом

1. Прочитай [`STATUS.md`](STATUS.md).
2. Для смысловых задач прочитай [`01-brand/brand-platform.md`](01-brand/brand-platform.md) целиком.
3. Проверь [`_meta/open-questions.md`](_meta/open-questions.md): пробел может быть уже осознанно зафиксирован.

## Как вносить материал

1. Сырой файл положи в `_inbox/` без переименования.
2. Определи, какое правило или факт из него следует.
3. Правило опиши в содержательном разделе; живой ассет положи в `04-assets/` или каталог продукта.
4. Добавь происхождение в `_meta/sources.md`, а первичный файл — в `_meta/source-manifest.json` с SHA-256.
5. Для технического доказательства используй `03-product/evidence/manifest.json`.
6. Обнови `STATUS.md`, `_meta/open-questions.md` и `_meta/changelog.md`.
7. Запусти:

```sh
node scripts/check.mjs
```

## Статусы

- `✅ зафиксировано` — подтверждено владельцем или напрямую задано каноническим документом.
- `🟡 черновик` — интерпретация, неполное правило или решение без подтверждения.
- `⬜ пусто` — материал или решение отсутствует.

Не повышай статус только потому, что формулировка выглядит убедительно.

## Продуктовые утверждения

Маркетинговая строка и доказательство — разные сущности. Перед использованием характеристик, безопасности, совместимости или сертификации проверь [`03-product/claims.md`](03-product/claims.md).

Утверждение со статусом `⛔` нельзя публиковать. `🟡` допустимо только во внутреннем черновике с явной пометкой.

## Ассеты и бинарные файлы

- Один живой файл — одна понятная роль.
- Ревизия продукта обязательна в имени рендера.
- Старую продуктовую ревизию не перезаписывай: перенеси в датированный архив.
- Не добавляй файлы шрифтов без документа лицензии.
- Не конвертируй Pantone в производственный цвет по изображению на экране.
- Если бинарные ревизии начнут регулярно расти, до следующей крупной загрузки подключи Git LFS.

## Перед передачей наружу

Пройди [`RELEASE_CHECKLIST.md`](RELEASE_CHECKLIST.md). Рабочий репозиторий и пакет для подрядчика — не одно и то же: во внешний пакет не должны попадать файлы шрифтов, сырьё и внутренние гипотезы.
