# Omu Design System

Единый источник правды по бренду Omu: правила, описания, ассеты.

## Установка

Одной фразой агенту — Claude Code, Codex и другим: **«Настрой дизайн-систему OMU по инструкции `SETUP.md` из https://github.com/borilya/omu-design-system. Шрифты лежат здесь: `<путь>`»**. Подробности — [SETUP.md](SETUP.md).

## С чего начать

- **[STATUS.md](STATUS.md)** — что уже зафиксировано, а что ещё черновик. Начни отсюда.
- **[01-brand/](01-brand/)** — кто такой Omu, для кого, каким голосом говорит.
- **[02-identity/](02-identity/)** — визуальный язык: логотип, цвет, типографика, правила кадра.
- **[03-product/](03-product/)** — изделие: концепт, CMF-спецификация, рендеры и допустимость продуктовых claims.
- **[04-assets/](04-assets/)** — файлы для скачивания. Шрифтов здесь нет: их выдаёт владелец, см. [04-assets/README.md](04-assets/README.md).
- **[06-design-system/](06-design-system/)** — код дизайн-системы: токены, компоненты, UI-киты, style guide. Открыть `06-design-system/OMU Style Guide.html` в браузере.
- **[_sources/](_sources/)** — закрытый архив первичных материалов; наличие файлов отслеживается через manifest.

## Как устроено

Правила и файлы разделены. `02-identity` объясняет, **как** пользоваться логотипом и цветом; `04-assets` содержит сами файлы. Это защита от ситуации, когда в проекте лежит пять версий логотипа и никто не знает, какая живая.

У каждого раздела есть статус зрелости. Опирайся только на `✅ зафиксировано` — остальное может измениться.

## Если ты подрядчик

Читай `01-brand/`, `02-identity/`, `03-product/`, бери файлы из `04-assets/`. Вопросы, на которые в системе нет ответа, скорее всего уже перечислены в [_meta/open-questions.md](_meta/open-questions.md) — если нет, спроси.

## Если ты пополняешь систему

Кидай материал в `_inbox/` как есть — не сортируй и не переименовывай. Разбор и раскладка происходят отдельным шагом.

Порядок внесения изменений описан в [CONTRIBUTING.md](CONTRIBUTING.md). Первичные источники учитываются в [_meta/source-manifest.json](_meta/source-manifest.json), технические доказательства — в [03-product/evidence/manifest.json](03-product/evidence/manifest.json). Перед внешней передачей материалов пройди [RELEASE_CHECKLIST.md](RELEASE_CHECKLIST.md), затем запусти:

```sh
node scripts/check.mjs
```
