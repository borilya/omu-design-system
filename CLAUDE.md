# Omu Design System — рабочая инструкция

Это репозиторий дизайн-системы бренда **Omu**. Здесь нет кода продукта — только правила, описания и ассеты.

**Что известно об Omu на сейчас:** концепт продукта существует у владельца, визуальная часть собрана частично. Позиционирование, айдентика и продуктовый концепт наполняются постепенно — смотри `STATUS.md`, чтобы понять, что уже истина, а что ещё нет.

## Роли системы

1. **Источник для AI** — читаю этот репозиторий, чтобы генерить лендинги, креативы, тексты и презентации в едином стиле без переобъяснений.
2. **Гайдлайн для людей** — можно отдать дизайнеру, агентству, новому сотруднику.
3. **Библиотека ассетов** — единственное место, где лежат живые файлы бренда.

## Карта

| Путь | Что внутри |
|---|---|
| `STATUS.md` | Таблица зрелости всех разделов. **Читать первым.** |
| `_inbox/` | Сырьё от владельца, ещё не разобранное. |
| `01-brand/` | Кто такой Omu: позиционирование, характер, tone of voice. |
| `02-identity/` | Визуальный язык **словами**: лого, цвет, типографика, правила визуала. |
| `02-identity/tokens.json` | Машиночитаемые цвета и типографика. |
| `03-product/` | Концепт продукта + рендеры с разбором. |
| `04-assets/` | Готовые **файлы**: логотипы, шрифты, изображения. |
| `05-applications/` | Как бренд живёт в мире: лендинг, соцсети, презентации. |
| `_meta/sources.md` | Откуда взято каждое правило. |
| `_meta/open-questions.md` | Что осознанно не решено. |
| `_meta/changelog.md` | История изменений системы. |
| `_meta/system-design.md` | Зачем система устроена именно так. |

Принцип разделения: `02-identity` читают, `04-assets` скачивают. Правила и файлы не смешиваются.

## Статусы

В шапке каждого содержательного файла стоит один статус:

- `✅ зафиксировано` — правило подтверждено владельцем, можно отдавать наружу и опираться при генерации.
- `🟡 черновик` — гипотеза (моя или владельца). **Нельзя** выдавать за истину бренда.
- `⬜ пусто` — материала ещё не было.

## Как работать с этим репозиторием

**Когда владелец вгружает материал** (файл в `_inbox/`, вложение в чат, ссылка на Figma):

1. Разобрать: понять, какое правило бренда из этого следует.
2. Описать словами в нужном разделе — не «вот файл логотипа», а минимальный размер, охранное поле, запрещённые применения.
3. Живые файлы положить в `04-assets/`, сырьё из `_inbox/` убрать после разбора.
4. Записать происхождение правила в `_meta/sources.md`.
5. Обновить `STATUS.md` и `_meta/changelog.md`.
6. Закрытые вопросы вычеркнуть из `_meta/open-questions.md`, новые — добавить.

**Жёсткое правило.** Ничего не выдумывать о бренде молча. Если пробел заполнен догадкой — статус `🟡 черновик`, и вопрос уходит в `_meta/open-questions.md`. Владелец должен видеть разницу между своим решением и моим предложением.

**Генерация по системе.** Опираться только на `✅ зафиксировано`. Если для задачи нужно то, чего нет или что в черновике — сказать об этом прямо, а не подставить похожее.
